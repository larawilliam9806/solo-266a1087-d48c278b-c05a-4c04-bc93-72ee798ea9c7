# 剧院出票日报补档 API

剧院只保留出票汇总单（按统计区间记录出票总数），且统计日期多有重叠。
本服务按**演出季整批交单**，把汇总单建模为差分约束，补算每日出票量的
最低/最高可能值，矛盾时给出可单独证实矛盾的一组单号。

- 框架：FastAPI + Pydantic v2
- 存档：SQLite（WAL 模式，数据落 `/data` 卷）
- 部署：Docker / Docker Compose
- 核算：NumPy 向量化全点对最长路（Floyd），单季最多 366 天

## 目录结构


## 业务规则与接口约定

### 交单 `POST /api/seasons/submissions`

按演出季整批交单，请求体：

```json
{
  "season_id": "S2026",
  "start_date": "2026-03-01",
  "end_date": "2026-03-05",
  "seen_batch": 1,
  "orders": [
    {"order_no": "A01", "start_date": "2026-03-01", "end_date": "2026-03-03", "total": 120},
    {"order_no": "A02", "start_date": "2026-03-01", "end_date": "2026-03-01", "total": 40}
  ]
}
```

- 填本季起止日，跨度（首尾均计入）**最多 366 天**；
- 每单填单号、季内统计首尾日、出票总数（非负整数）；
- **首次交单不填 `seen_batch`**；再次交单必须携带当前生效批号；
- 所见批号仍有效时，新单与核算结果在同一事务中**一同生效**，
  批号 +1；批号已过期则返回 `409`，**沿用当前批**，数据不变；
- 单据本身互相矛盾不算交单失败：矛盾批照常存档生效（批号前进），
  核算查询给出矛盾证据；
- 参数/日期非法（超 366 天、单据超出季范围、单号重复、负数等）返回 `422`。

### 核算查询 `GET /api/seasons/{season_id}/accounting`

返回当前生效批号、该批单据、逐日核算结果、矛盾证据：

- `batch_no`：当前生效批号；
- 每日给出 `min_tickets` / `max_tickets`，**`max_tickets = null` 表示无上限**；
- `official_tickets`：**正式供数，只列上下限相同的日值**；
- `feasible = false` 时 `contradiction_proof` 给出能**单独证实矛盾**的
  一组单号（该子集自身已矛盾，且去掉其中任意一单即不再矛盾）。

### 辅助接口

- `GET /api/seasons`：各演出季当前批号与可行性一览；
- `GET /health`：存活探针。

### 订正试算 `GET /api/seasons/{season_id}/batches/{batch_no}/corrections`

拿到矛盾批后，票房据此找出**只改一张汇总单就能让整批成立**的全部单号。
按演出季和当前矛盾批号查询（批号必须是当前生效批号，且该批 `feasible=false`）：

- `options`：所有可单独订正的单据，逐单给出 `current_total`（原件总数）、
  `min_total` / `max_total`（出票总数可填的**最小/最大整数**，闭区间，
  沿用原有总数上限 `1e12`，无界方向即顶到上限/0）；
- 试算每张单时**保留其余全部单据**，只把候选单从约束图中移除；
- 只评估已存 `contradiction_proof` 中的单据：证据之外的单据不参与任何
  试算核算，**证据以外的单据再增加，整季核算次数也不会随之增加**
  （核算次数 = 证据中的单数，每次为一次压缩图 Floyd）；
- `options` 为空表示矛盾需要同时改多张，没有任何单据能单独救场；
- 批号已变（`409`）、该批本身可行（`409`）、季不存在（`404`）均不试算。
- 只读接口、不持写锁：**试算期间本季仍可从原入口（交单/订正）换交**。

### 订正提交 `POST /api/seasons/{season_id}/corrections`

复核原件后，凭所见批号、单号和新总数提交订正：

```json
{"seen_batch": 3, "order_no": "A01", "new_total": 88}
```

- **只改这一张单的总数**，其余单据（区间与数值）逐字保留，重新整批核算；
- 只有整批成立时才按**新批号**发布单据与核算结果（同一事务原子提交），
  返回新批号与逐日核算；
- 发布前批号已变（`409`）、订正后整批仍无解（`409`）或保存失败，
  均**不产生新批，沿用当时的生效批次**；
- 单号不在该批（`404`）、新总数超出 `0..1e12`（`422`）同样被拒。

## 核算原理

设季内第 d 日出票量为非负整数 x_d，前缀和 p_0=0、p_k=Σx。

| 业务含义 | 约束 | 最长路边 |
| --- | --- | --- |
| 出票量非负 | p_d − p_{d−1} ≥ 0 | d−1 → d，权 0 |
| 单据 [l,r] 共 t 张 | p_r − p_{l−1} = t | l−1 → r 权 t；r → l−1 权 −t |

全点对最长路之后：

- 出现 `dist[i][i] > 0`（正环）⇔ 约束无解 ⇔ 单据矛盾；
- 日最低出票量 = `dist[d−1][d]`；
- 日最高出票量 = `−dist[d][d−1]`，若 d → d−1 不可达则**无上限**；
- 上下限相等即该日被单据唯一确定，进入正式供数。

整数性保证：单据约束矩阵是连续 1 矩阵（interval matrix），属于全幺模
矩阵，线性松弛可行域的极点全为整数，因此"非负整数日账"的可行性与
逐日极值与最长路（线性松弛）结论完全一致，不会出现 LP 有解但整数无解。

矛盾证据提取：边 u→v（权 w）落在某个正环上当且仅当
`w + dist[v][u] > 0`；收集这些边所属单据后，再逐单尝试移除并重新判定，
得到包含意义下极小的矛盾单据组。

订正试算原理：候选单 o（区间 [l,r]，记前缀节点 a=l−1、b=r）的两条边
被移除后，对"其余全部单据"的压缩图跑最长路：

- 余下图仍含正环 ⇒ 只改 o 一张无救，该单不出现在 `options`；
- 余下图可行时，新总数 t（约束 p_b − p_a = t）必须同时满足
  - `t ≥ dist[a][b]`（a→b 最长路，不可达则下界为 0）；
  - `t ≤ −dist[b][a]`（b→a 最长路取负，不可达则无上限）；
  再与非负约束和原有总数上限 `1e12` 取交，即得可填整数闭区间。
  全幺模性保证区间内每个整数 t 都对应一套非负整数日账。

## 并发与一致性

- 每个演出季一把进程内互斥锁，同季交单/订正串行化；不同演出季互不阻塞，
  核算与试算期间其他演出季仍可正常交单；
- 锁内开启 SQLite `BEGIN IMMEDIATE` 事务，先核对所见批号再整批写入，
  单据与核算结论原子提交；
- 核算查询与订正试算为只读且不持写锁：试算期间本季仍可从原入口换交，
  交单/订正失败时查询与试算结果不受影响；
- 订正只在整批重新核算可行时才发布新批；批号过期、订正后仍无解或保存失败，
  全部回滚并沿用当时的生效批次。
